# 王立地図院 — 地下世界地理台帳・管理規約 v0.1（提案）

> 2026-11-25／v0.1の設計・試作時点の検討履歴。後続の作者依頼により [v0.2運用規約](../world/underground/README.md) と最小台帳・検証コードを同PRに実装した。以後の規約はv0.2を優先。以下は当時の記録であり、具体的な地理や採番細則の採用を意味しない。
> 作者・DM・制作エージェント向け。Public GitHub はアクセス制御ではない。WORLD_POLICY.md の公開境界を維持する。

## 1. 目的と原則

作中の王立地図院の調査・採番・地図更新を、GitHub 上の持続的な地理台帳として再現する。シナリオの準備と実際のプレイによって必要な範囲だけを確定し、空白を保ちつつ、過去セッションの地理的事実と矛盾しない世界を育てる。
- 台帳は地理の正本、地図は台帳から派生する表示物。既存世界設定の自然法則・採用済み用語は world/02_マナ・魔石・迷宮と社会.md 等を優先する。
- 設定の採否、作中での認知、DMが知る真相、現在の物理状態を混同しない。
- 作者の承認なく確定事項を追加・上書きしない。知らないことを null として保持し、未踏域の行き先・距離・座標を推測で埋めない。
- 経路の変化（作中の崩落等）と設定訂正（編集上の誤り）を区別する。セッションで観測されたことと NPC の発言・PC の推測も区別する。

## 2. 最小データモデル

| 種別 | 正本に持つ情報 |
|---|---|
| NODE | 地図院の登録番号、種別（分岐・空洞・竪穴入口・乗降場・地形等）、名称/別名（任意）、位置制約、説明、根拠 |
| SEGMENT | 地図院の登録番号、両端NODE（未知側は null）、実際の経路長・移動時間の条件付き範囲、移動手段、上下関係、方向・通行性、整備状況、必要設備、根拠 |
| ROUTE | 地図院の路線番号（未採番なら null）、順序付きSEGMENT参照（方向を含む）、正式名称/通称/顕彰の根拠、採番史 |
| FACILITY | 地図院の登録番号、設置地点/接続区間、設備種別、名称、利用条件、稼働状態、建設・改修の履歴 |
| REPORT | セッションまたは作中の報告。観測・証言・仮説、観測日時/報告日時、誰が何を知ったか、参照ID、原記録へのリンク |

- **2026-11-25 作者追加決定：地図院の表記とGitHubの表記を統合する。NODE・SEGMENT・ROUTE・FACILITYは制作側だけの分類ではなく、作中の王立地図院が採用する地理管理概念とする。** 地図院の登録識別子をGitHubの参照キーとして共用し、登録済みの対象に別系統の制作管理番号を必須としない。
- 表記例（未決）：NODE 34（N-34）、SEGMENT 82（S-82）、ROUTE 65（R-65）、FACILITY 8（F-8）。略記は同じ番号の機械可読表記であり別番号ではない。番号体系・接頭辞・桁数は後で決める。地図院の登録番号は原則として再利用せず、再編・改番時は旧番号と後継対象の関係を保持する。PRで衝突を検査する。
- 地図院未登録の対象やDM限定の草案には正式番号を捏造しない。必要なら正式登録番号とは明確に区別した暫定参照キーを用いる。正式登録時に対応を記録する。作中の呼称と地図院の正式名称は原則一致し、実際に異称・旧称があるときのみ併記する。
- ルート番号は地図院の交通網体系を目指し、歴史的例外を許容。桁数・英字等の正式規則は未決。ルート3/65/752等は議論用の例示で、登録しない。道路名は番号と独立し、複数区間や複数路線にまたがってよい。名前の対象範囲を参照で表す。主要幹線には貢献者を顕彰した名称、横道・深部は無名の傾向。
- 同じ物理区間が複数路線に含まれてもよい。途中で分岐が見つかったら区間を分割し、旧登録番号を廃止扱いにして後継区間へリンク、ルート番号・歴史的参照は維持。別ルートへの接続を勝手に推定しない。
- TREEは人工の足場・通路等の施設構造、ROUTEは道・航路。昇降機や橋は施設として区間に参照させる。HOMEは地上とTERMINALを結ぶ固有名。地下の下降路もSEGMENTで表し、階層番号を必須にしない。

## 3. 三次元地理と空白

初期は接続関係と相対関係だけで十分。例：AよりBが低い、AからBまで徒歩で20〜30分（条件を付す）。方位・標高・距離・座標は必要時に確定する。
- 座標を使う場合は共通基準を作者が承認してから、単位m、軸・原点・座標精度を明示する。正確な座標と概略位置を分ける。天井高、地表からの深度、標高差、経路長、直線距離は別の量。高さの基準を混用しない。
- 未探索の横穴は入口と開口の方向だけを記録し、SEGMENTの未知側はnull。仮の空洞を確定NODEとして追加しない。未測量だが存在が確認された地点と、仮説上の地点を分ける。
- 自然洞窟・縦穴・空洞・地上への裂け目は高さの異なる経路が交差し得る。平面上で交差していても接続とは限らない。
- 位置制約を矛盾なく増やす。閉ループの高低差や経路長と直線距離の整合は同じ基準と精度がある場合のみ検証。定量情報を持たない段階では無理に検査しない。

## 4. 確度・認知・時点

| 軸 | 値の例 |
|---|---|
| 制作上の採否 | accepted / provisional / draft |
| 作中の知識（記録単位） | surveyed / observed / reported / inferred / unknown |
| 区間の通行状態（時点付き） | passable / restricted / blocked / unknown |
| 整備状態 | natural / marked / improved / maintained / unknown |
| 開示範囲 | DM専用 / 地図院内 / PCに伝達済み / 一般に知られる（知識主体や会員階級を必要に応じ記録） |

採用された「噂」は噂が存在するという事実であり、噂の内容が物理的真実ではない。DM設定・地図院の予測・PCの手元の地図を混同しない。作中時点とセッション番号・実施日を別に記録し、未決の暦は強制しない。過去の物理状態と現在値を追跡できるように変更履歴を残す。プレイヤーが持つ古い地図は取得時点の版として保存する。

## 5. 保存先（提案）

- world/underground/README.md：運用・データ仕様・台帳入口。
- world/underground/atlas.json：初期の小規模な確定地理台帳（nodes, segments, routes, facilities）。JSONを唯一の構造化正本にし、説明文は参照で補う。規模が拡大した時点で種別/地域別の分割を検討。
- dm/underground/atlas.json：ネタバレを含む作者承認済み地理・DM限定の補完レコードのみ。同じ事実をworldとdmに複製しない。両方にまたがるID・参照をDM用検査で解決する。公開用生成処理はdmを入力にしない。公開可能になった項目は移動しIDを維持する。
- dm/sessions/ または既存のセッション記録：プレイ済みの観測と情報開示履歴。実際の既存構成を調べてから選び、二重のセッション正本を作らない。実際に秘匿すべき情報はPublic GitHubに置かない。
- notes/：未採用の地理仮説、管理規約案、採用前の検討。DMネタバレの草案はdm/の既存の規則に従う。
- scripts/verify-underground.*：将来の検査。ActionsでPR検査を実行する構想。
- 生成地図：必要時に台帳から自動生成。概略接続図、断面図、座標が整った地域の地図、セッション時点の図を区別する。手描き美術は補助資料として版と対応IDを持たせる。Pagesの公開は個別承認し、既存SECTIONS/llms.txt規約に従う。

初期はJSONとMarkdownの小さな構成で開始し、大規模GIS・3Dエンジン・WebUIは作らない。台帳の場所をworld/READMEとdm/READMEから案内し、採用後にAGENTS.mdへ参照必須を追記する。

## 6. セッション運用

1. 準備：現行台帳・対象区間の前回ログ・既存設定を確認。再訪先の経路、障害、移動時間等を読み出す。追加地理はDM草案として既存と照合し、通らなかった候補をプレイ済み扱いしない。
2. プレイ中：ルート・分岐・上下関係・所要時間・目印・発見・PCが知ったことを簡潔にメモ。即興で追加した事実は特に記録。発言、推測、直接観測を分ける。
3. 終了後：セッションの原記録を保存し、必要な地理差分だけをPRにする。新規・変更・未解決の矛盾を明記。既存ID・同名地点・接続・年代・公開範囲を照合。
4. DM/作者確認：承認済み事実を台帳へ反映し、未決の部分は未決のままにする。検査を通してマージ。セッション後に確定したGitコミットを原記録に関連付ける。
5. 再訪：現在値と前回訪問時の記録を比較。崩落や整備など、実際に作中で起きた変更に従う。誤りが見つかったら無断で書き換えず、DMの判断（記憶違い・測量誤差・作中変化・明示的な設定訂正）を記録する。

作中の地図院への報告はDMの台帳更新とは別イベント。PCが帰還していない/報告していない場合、地図院の知識は自動更新しない。

## 7. 検証・受け入れ条件

CIで必須エラー：重複ID、参照先不明（未知端nullは可）、ルートの区間連続性/方向の矛盾、現行の公式番号重複、廃止IDの再利用、確定値の根拠欠落、不正な負の距離、採用状態の不正値、公開生成物へのDM由来情報混入（機械で確認可能な参照境界）。更新PRで履歴・変更理由を確認。
警告：座標/高低差の矛盾候補、所要時間の極端な変化、閉鎖区間を通常の移動案が通る、同名・類似地点、根拠の古い記録、既存セッションとの差分。未知値はエラーにしない。自動検査は物語の意味・自然描写・漏洩すべてを保証できず、人間のレビューを必須とする。

## 8. 初期投入と段階導入

既存採用の地上→HOME→TERMINAL→PORT/GATEという接続骨格だけを既存正本と照合して登録する。正確な座標・距離・配置は未決。第一話の湖の位置・経路はPR #51等のDM草案を参照して作者の採用を待ち、例示路線番号を勝手に割り当てない。
- 第1段階：規約承認、最小台帳・スキーマ・検査、既存採用済み接続の登録。
- 第2段階：第一話の準備・プレイ後の更新を実際に試し、必要な項目を調整。
- 第3段階：規模が拡大したら接続図/断面図、検索、経路計算、座標化等を追加する。

## 9. 決めないこと

現時点で地下全体の形、地理区分、個別路線番号、名前、深度、方位、距離、世界暦、昇降機の配置・詳細、地図院の採番細則は確定しない。管理規約の採用と地理設定の採用は別の判断である。

### 判明した仕様の不足と修正候補
- P0：地図院とGitHubの番号共用は維持。地図院未登録の実在地点だけに暫定キー（例：tmp:session-01:opening-a）を許す。正式登録時に対応表を残し、現行参照を更新、過去の原記録と配布地図は不変。未登録を正式番号で表さない。作者採用・報告受領・地図院の測量登録は別イベント。
- P0：物理的な真実と観測・報告を別レコードにする。主体ごとの知識と有効時点をREPORTに記録。別人の相反する深度等は上書きせず仮説・証言として保持。地図院の登録番号だけでは真実を保証しない。承認済みの地下事実を台帳に追加することと作中での情報公開は別。
- P0：区間分割を一括変更として扱い、全ROUTE・施設参照を更新する。逆向き経路は後継区間の順序と方向を逆転。旧番号は失効理由・後継区間（順序付き）・時点を保持し、物理的閉鎖とは別にする。旧報告がどの部分を指したか不明なら無理に後継の片方に帰属させない。統合・改番にも同様の履歴が必要。
- P0：通行性は区間全体の単一フラグだけでは不足。SEGMENTの移動手段別・方向別・条件別の可否と、FACILITYの稼働状態を分ける。昇降機故障はその手段を不可にするが、既存のロープ下降を自動的に不可にしない。ルート指定と現在通行可能かも別。
- P0：公開範囲の参照閉包をチェックする。world側レコードからdm側の秘匿端点を直接公開しない。開示可能な入口と未知端で表現し、DM補完情報は別の事実として関連付ける。PC向け配布図の知識時点・主体・根拠を固定。GitHub自体がPublicであり実際の秘匿は保証しない。
- P1：未知端nullは未探索開口の終端として許容するが、別区間へ接続する中間点にはできない。空洞全体を一点と見なさず、必要になったとき入口・出口・湖岸などのノードを追加し、空洞内移動も区間で表す。すべての曲がり角に番号を付けず、案内・測量・接続の意味がある地点に限定する。平面の交差だけでは接続にしない。
- P1：標高差の閉ループ検査は同一基準・誤差範囲で行う。厳密な矛盾と測量誤差や未測量を区別。試作は厳密値のみで範囲制約・座標系変換は未実装。
- P1：並行PRで番号を割り当てる際に衝突をマージ前に検知する。同一キーのJSON上書きはマージ後の重複検査だけでは検出できない。最新mainに対する再検査と、既存レコードの無断上書き検査を要する。作中の番号が告知済みなら黙って変更せず作者判断と履歴を残す。
- P1：作中の有効時点、観測時点、報告時点、制作上の更新時点を分ける。Gitのコミット順だけで作中時系列を表さない。作中の絶対暦は未設定でもセッション・場面の順序を使える。
- P2：日常の案内はROUTE番号・道名、専門測量はNODE/SEGMENT/FACILITY番号で表し、セッション中のDMの入力は自然文の簡易記録でよい。終了後に地図院台帳へ構造化する。採番体系、英字接頭辞、桁数、具体的な地図は本レビューで確定しない。

### 残課題
試作では完全なスキーマ、永続化、歴史時点の自動再構築、報告の照合/同一地点判定、複数情報主体向けの生成、GitHub上の実際の並行マージ、精度範囲を用いた地理検証は実装していない。次段階では作者の方針承認後に小規模な実台帳・テスト・CIを導入する。現行の正本、公開Pagesおよび具体的な地理は変更しない。
